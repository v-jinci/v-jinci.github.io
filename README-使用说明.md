## 一、6 个 bat，按文件名数字顺序用

前面那个数字就是推荐顺序，**平时只会用到 1 和 2**：

| 双击这个 | 干什么 | 什么时候用 |
| --- | --- | --- |
| `1-发布到网站.bat` | 发布上线：本地 → GitHub → 云端自动编译 → 网站更新 | **写完文章、改完设置后**（最常用） |
| `2-打开写作后台.bat` | 启动本地写作后台，自动打开浏览器 | 想写新文章、改旧文章 |
| `3-本地预览.bat` | 只看效果，不改内容 | 想先看看改成长什么样 |
| `4-同步云端文章.bat` | 把手机上写的文章拉到本地 | 在手机上发过文章之后 |
| `5-首次配置GitHub.bat` | 粘贴 GitHub 令牌 | **只需要一次**，配好了就不用管 |
| `6-恢复备份.bat` | 把文章恢复到某次发布前的样子 | **误删、写错、内容莫名变了的时候** |

> 双击后黑窗口里会显示 `[1/4] 检查本机环境` 这样的进度，每一步下面还写着一行白话说明。
> 卡住了就把窗口里的内容发我，不用自己猜是哪一步出问题。
> 另外 `_run.bat` 是这几个 bat 内部调用的，**不用你双击**。

### 发布是怎么走的

```
改文章（本地后台 / 记事本 / 手机上）
   ↓
hexo-src 分支（源码：_posts、_config.yml）
   ↓  GitHub Actions 自动编译（约 1 分钟，免费）
master 分支（编译后的网页）
   ↓
https://v-jinci.github.io
```

好处：**本地发布和网页编辑走的是同一条流水线，不会互相覆盖**。`1-发布到网站.bat` 每次会先取回线上最新的源码，再叠加上你的改动，所以你在别处写过的文章不会丢。

- 看构建进度：https://github.com/v-jinci/v-jinci.github.io/actions
- `1-发布到网站.bat` 若提示「没有检测到任何改动」，说明本地和线上一致，不用发。

## 二、写一篇日志（三步）

1. 双击 `2-打开写作后台.bat`，浏览器会打开后台。
2. 点 **Posts → 右上角 New Post**，**先填一个真标题**（留空的话会自动叫「日期2026年11月10日」这种名字），再写正文。左边写 Markdown，右边实时预览。
3. 写完点右上角 **Publish**，等 1-2 分钟线上就有了。

不想走后台也行：把 `.md` 文件丢进 `source/_posts/`，一样会被识别。

### Markdown 最常用的几个

```markdown
## 二级标题
**加粗**  *斜体*  [链接](https://example.com)
- 无序列表
1. 有序列表

> 引用一段话

![图片说明](图片名.jpg)
```

### 排版小抄（本地写、Pages CMS 写都通用）

**先弄懂「引用块」是什么**：就是正文里一段带竖线、底色浅浅的「框」。
写出来只用到一个小小的 `>` 符号（大于号，后面加一个空格）。比如源码这样写：

```
> 提示：明天上午十点开会，别忘了带笔记本。
```

发布后就会变成一条蓝色提示卡片。所以表格里说的「引用块的第一行写 提示：」
意思就是：**在 `>` 后面先打「提示：」，再打你想说的话**，四个词换着用就是四种颜色：

```
> 提示：蓝色，适合小建议
> 注意：黄色，容易出错的地方
> 重点：紫色，最想让读者记住的
> 警告：红色，千万别做的事
```

不想手写符号也行：本地写作页点工具条上的「💡 提示卡片」下拉，选一个，
它会自动插好整段，你把里面的占位文字改成自己的就行。

这些「写法约定」网站会自动认出来变成好看的样式，不用装任何东西：

| 想要的效果 | 怎么写 |
|---|---|
| 提示框（蓝色 💡） | 引用块的第一行写 `提示：内容` |
| 注意框（黄色 ⚠️） | 引用块的第一行写 `注意：内容` |
| 重点框（紫色 📌） | 引用块的第一行写 `重点：内容` |
| 警告框（红色 🚫） | 引用块的第一行写 `警告：内容` |
| 折叠块（点标题展开） | 引用块的第一行写 `折叠：标题`，后面跟内容 |
| 金句（居中大字） | 引用块里只写一句短话（60 字以内） |
| 图注（图片下方小字） | 图片的下一行写 `*说明文字*`（前后各一个星号） |
| 两图并排 | 连着插两张图，中间不空行（三张也行） |
| 步骤条（带圆圈数字） | 有序列表的第一项写 `步骤：` 开头 |
| 按钮链接（圆角大按钮） | 单独一行写 `【按钮】[文字](网址)` |
| 表格美化 | 正常插表格即可，自动加表头底色、手机上可横向滑动 |
| 图片大小 / 环绕 | 图片地址后加 `?w=60%`、`?f=r`（详见「五、图片怎么放」） |

**「按钮」在 Pages CMS 里怎么写**（没有专门的按钮按钮，就是打三个字 + 插一个链接）：

1. 先**回车另起一段**（这一段里不能有别的字）；
2. 打上 `【按钮】`（中文方括号 + 按钮两个字，原样照抄）；
3. 紧接着点工具栏的**链接**按钮（链条 🔗 图标），填网址和按钮文字；
4. 保存。发布后这一段就变成一个居中的圆角按钮，`【按钮】` 三个字不会显示出来。

段落里多打了别的字、或者没插链接，它就只当普通文字，不会出按钮——这是故意的，防止误伤。

### 可视化写作页（像 Word，推荐用这个）

打开 <http://localhost:4000/write>（也可以在 `/site` 页面顶部点「写文章（可视化）」）。

- 工具条：标题级别、字号、颜色、高亮、加粗/斜体/下划线/删除线、左中右对齐、列表、引用、代码、链接、表格、分割线，全都不用记写法。
- 「💡 提示卡片」下拉：一键插入 提示 / 注意 / 重点 / 警告 / 折叠 / 金句，插入后编辑区里就直接显示颜色，所见即所得；手打的引用块只要第一行以这些词开头，也会自动上色。
- 「🔘 按钮」：点一下，填按钮文字和网址，自动插好；发布后变成圆角大按钮（编辑区里显示「【按钮】文字」是正常的）。
- 图片：点「🖼 图片」上传（自动压成 webp），或直接把图粘进正文。点一下图片，底部会出现一条控制栏：**拖图片右下角的圆点改大小**；选「图在左·文字在右」，文字就绕到图片旁边，不再空到下面。
- 从 Word、网页复制的内容直接粘进来，会自动清洗成干净格式（颜色、字号、粗体会保留）。
- 「存草稿」存进 `source/_drafts`，线上看不到；点「保存并发布」才真正上线。
- 右上角「源码」按钮可以切回 Markdown；打开旧文章时默认是源码模式，防止把 hexo 特殊写法改坏。

## 三、在任何设备上写（Pages CMS 表单后台）

不想开电脑、想在手机浏览器里写的时候用这个。保存后 GitHub 自动编译，1-2 分钟上线，电脑可以一直关着。

### 一次性开通（三步，约 2 分钟）

1. 电脑打开 https://pagescms.org → 点 **Sign in with GitHub**，用 `v-jinci` 账号授权。
2. 点 **Add repository**，选 `v-jinci/v-jinci.github.io`。
   若列表里没有它，在 GitHub 的授权页点 **Grant / Select repositories** 把这个仓库加进去。
3. **分支一定选 `hexo-src`**，不要选 `master`。
   `master` 是编译后的成品页面，在那儿改等于白改，下一次构建就被覆盖。

进去之后左侧应看到两组：**文章**、**独立页面**（关于 / 友链 / 留言板 / 编年史）。

### 怎么用

- 点 **文章 → New**：标题、发布日期、摘要、标签、分类都是表单，正文是富文本编辑器，可以直接往里面拖图片。
- 改完点 **Save**，等 1-2 分钟刷新线上就有了。
- 构建进度：https://github.com/v-jinci/v-jinci.github.io/actions

### 文章表单里的开关都是干嘛的（2026-11-13 更新）

| 字段 | 作用 |
|---|---|
| 摘要 | 首页卡片显示的两行简介；不填会自动截正文开头，常常截得难看，建议自己写 |
| 封面图 | 首页卡片和「上一篇/下一篇」的底图；不填用深色渐变 |
| 系列 / 专栏 | 填同一个名字的文章，文末自动出现「📚 系列合集」目录互相跳转（第二篇起才显示） |
| 置顶 | 选了就排首页最前，标题旁有小图钉；多篇置顶时数字小的更靠前 |
| 显示评论区 | 默认开。公告类文章可以关，打开更快 |
| 显示右侧目录 | 默认开。短文关掉更清爽 |
| 访问密码 | 填了就要输密码才能看，正文在源码里也是加密的 |
| 正文图片宽度 / 排版 | 整篇图片的默认大小和环绕方向（某一张可单独用 `?w=` `?f=` 覆盖） |
| 转载来源名称 / 链接 | 转载别处文章才填，文末自动出「📎 本文转载自 …」；原创留空 |

正文里的排版写法（提示框、折叠、图注、并排、步骤、按钮）见第二节「排版小抄」——
在 Pages CMS 里用编辑器自带的「引用块 / 图片 / 列表」按钮就能写出来，手机上也好用。

### 图片：三种传法（2026-11-11 二次确认过）

1. **正文里插图（最常用）**：在正文里**输入一个斜杠 `/`**，会弹出命令菜单 → 选 **Image（图片）**，
   弹窗里可以**选已有图片或直接上传**。也可以**把图片文件直接拖进正文**、或截图后 **Ctrl+V 粘贴**。
   > 注意：正文编辑器的工具栏上**没有**图片按钮，入口就是 `/` 菜单、拖拽和粘贴，这是 Pages CMS 的设计。
   > 拖拽 / 粘贴能用的大前提是 `.pages.yml` 里 `media` 配置正确（现在是「数组 + name: images」的写法，别改回单对象）。
2. **封面图字段**：文章表单里的「封面图」格子，点它上传，
   这张图会用作文章底部「上一篇 / 下一篇」卡片的背景。
3. **图片库**：左侧栏 **图片库 / Media** → Upload → 复制路径，粘到正文里（同一个目录，两边通用）。

### 四个注意

1. **新文章的文件名 = 日期 + 标题**（例如 `2026-11-11-一点闲言碎语.md`）。
   这是特意改的：以前只按标题命名，**两篇同名文章会直接互相覆盖**，写过的东西就没了。
   现在带日期前缀，重名也不会盖掉旧文。文件名只在新建时按标题自动生成，改标题不会改文件名，所以改标题是安全的。
2. 图片会上传到 `source/img/`，正文里自动写成 `/img/xxx.png`，本地 Hexo 同样能用。
3. 表单里没列出的 front-matter（`top_img`、`type` 等）**不会丢** —— `.pages.yml` 里开了 `settings.content.merge: true`，这是关键，别删。
4. 如果保存时它提示要创建 **Pull Request**（部分版本这样），去 GitHub 点一下 **Merge** 即可，同样会触发构建。

> 手机适合短篇和随手记；长文还是本地后台（`2-打开写作后台.bat`）或 Typora 更舒服。

### 3.5 备用网页编辑器（2026-11-14 新增，与 Pages CMS 并存不冲突）

两套都是直接改 GitHub 仓库里的文件，和 Pages CMS 三选一随便用：

| 编辑器 | 打开地址 | 登录方式 | 特点 |
|---|---|---|---|
| **Sveltia** | `https://你的域名/cms/` | 点「使用访问令牌登录」→ 粘贴 GitHub 令牌（生成地址 <https://github.com/settings/tokens>，勾选 `repo`） | 界面已中文、速度快、表单和 Pages CMS 基本一样；也可以点「使用本地仓库」直接编辑本地文件 |
| **Tina** | `https://你的域名/admin/` 或 <https://app.tina.io> | 打开 `/admin/` → 点橙色 **Log in** → 用 GitHub 账号登录 TinaCloud | 编辑手感最像 Word（表单式编辑）；clientId / token 已填好在 `tina/config.ts` |

**Tina 补充说明**：
- 线上的 `/admin/` 是 Tina 的登录页（发布脚本会把 `source/admin/` 原样带上）；本地预览时 `/admin` 被旧插件占用属正常，看线上即可。
- app.tina.io 点进项目后如果看不到内容列表，去项目的 **Branches** 页签添加 `hexo-src` 并设为默认分支。
- 改过 `tina/config.ts` 的字段后要重新生成后台页面：运行 `npm run tina`（等于 `tinacms build`），再把 `public/admin/` 复制到 `source/admin/`。

排错：Sveltia 打不开时先确认 `/libs/sveltia/sveltia-cms.js` 能访问；配置在 `source/cms/config.yml`（`_config.yml` 里用 `skip_render` 保证它原样发布）。`/admin` 这个地址被旧后台占用了，所以 Sveltia 用的是 `/cms`。

## 四、把云端的文章同步回本地

在手机 / 网页上写的文章，存在 GitHub 上，本地 `source/_posts` 里一开始是**没有**的。三种同步方式：

| 方式 | 怎么触发 | 适合 |
| --- | --- | --- |
| 手动 | 双击 `4-同步云端文章.bat` | 想起来了点一下 |
| **启动时自动** | 双击 `2-打开写作后台.bat` 或 `3-本地预览.bat` 时，先拉一次再启动 | 推荐，平时不用管 |
| 定时自动 | Windows 任务计划（见本节目末） | 电脑长期开着 |

### 覆盖规则（四句话）

1. 线上有、本地没有 → **直接拉下来**（新文章）
2. 线上改了、本地没动过 → **用线上的覆盖本地**
3. 只有本地改了 → **不动**，等你 `publish` 时推上去（会提示「本地有 N 个改动还没发布」）
4. 两边都改了 → **保留本地**，把文件名列出来让你自己决定

判断依据是根目录的 `.sync-state.json`：记录上次同步时每个文件的指纹（文本文件忽略 CRLF/LF 差异，所以不会因为换行不同就误判）。这个文件可以删，删了不影响使用，只是下次同步没有比对基准，会按「保留本地」处理。

### 让它定时自动跑

`4-同步云端文章.bat` 结尾有 `pause`（方便你看结果），不适合放到计划任务里。用 `_run.bat` 更合适：

```bat
schtasks /Create /TN "BlogSync" /TR "cmd /c \"C:\Users\renwe\WorkBuddy\2026-11-10-18-43-13\_run.bat\" sync" /SC MINUTE /MO 30 /F
```

删掉：`schtasks /Delete /TN "BlogSync" /F`

> 这条命令要改系统计划任务，我没替你执行。想装的话跟我说一声，我帮你跑。

## 六、想改站点信息，只改这两个文件

| 文件 | 改什么 |
| --- | --- |
| `_config.yml` | 站点标题、副标题、作者、网址、每页文章数 |
| `_config.butterfly.yml` | 顶部导航、头像、个人简介、侧边栏卡片、深色模式、搜索 |

改完 `Ctrl+C` 关掉服务窗口，再双击 `2-打开写作后台.bat` 就能看到变化。

### 后台有 8 个分区（<http://localhost:4000/site>）

| 分区 | 能改什么 |
| --- | --- |
| **基本信息** | 站点标题、作者、副标题、描述、关键词、语言、对外邮箱、GitHub、页脚起始年份与附加文字、首页轮播标语（一行一句）+ **打字速度 / 停顿 / 删字速度 / 是否循环 / 字号 / 字间距 / 字重 / 颜色** |
| **联系方式** | 「关于」页的联系方式卡片：GitHub、邮箱之外可加**微信、QQ、Telegram、微博、B站**等；填链接就直接跳转，不填就点一下弹窗（显示账号 + 二维码 + 备注，带复制按钮）；可传二维码、可隐藏、可排序 |
| **外观图片** | **主页背景（多图轮播 / 视频背景 + 切换间隔 / 作用范围 / 压暗程度）**、首页顶部大图、侧边栏头像、**浏览器标签上的小图标 favicon**、**文章底部「上一篇/下一篇」背景**、**页脚背景**、作者简介、公告，以及 5 个开关（侧边栏 / 目录 / 深色按钮 / 阅读模式 / 头像旋转）、首页摘要字数 |
| **导航菜单** | 顶部导航的增删、改名、换图标、上下调顺序。改完保存即生效 |
| **下载区** | 上传文件到本站，或填网盘链接；大小自动读、可隐藏、可加日期 |
| **页面密码** | 给任意一个页面单独设密码（关于 / 下载区 / 留言板 / 友链 / 编年史 / 归档 / 标签 / 分类），可加、可改、可取消 |
| **评论区** | 开 / 关评论、改服务地址、访客是否免登录 |
| **留言管理** | 审核制留言（备用方案，现在留言板走 Waline） |

**主页背景小抄**：
- 图片放 2 张以上才轮播，1 张就是固定背景；顺序 = 列表顺序（↑↓ 调整）。
- 传了视频就用视频，图片只当「加载前的封面」；建议 6–12 秒、无音轨、≤ 15MB。
- 标题看不清就把「压暗程度」调大（0–60）。
- 都不设置 = 还是用「首页顶部大图」那张图。

改完点「保存」，预览立刻更新；点「保存并发布到线上」就推送并触发云端编译，
1-2 分钟后网站更新。**这个页面只在本机开着服务时能访问，别人打不开，安全。**

三处容易踩的小坑：

## 七、第一次发布要准备 GitHub 令牌

发布配置已经写好了：

```yaml
repo: https://github.com/v-jinci/v-jinci.github.io.git
branch: master
```

GitHub 早就不允许用登录密码推送了，需要一次性弄个令牌：

1. 打开 GitHub → 右上头像 → **Settings** → 左侧最下 **Developer settings**
   → **Personal access tokens** → **Tokens (classic)** → **Generate new token**
2. 勾选 `repo` 和 `workflow` 两项（`workflow` 是自动编译必需的），生成后**复制那串字符**（只显示一次）
3. 双击 `5-首次配置GitHub.bat`，粘贴一次令牌。它会当场向 GitHub 验证，通过才算成功。
4. 之后双击 `1-发布到网站.bat` 就是全自动的，不会再问账号密码。

> 换电脑、令牌过期或被撤销时，重跑一次 `5-首次配置GitHub.bat` 覆盖即可。

## 九、GitHub 打不开 / 后台登录不上（三个老问题的解法）

### 1. 留言板后台「密码明明对，却提示密码错误」

**原因找到了**：`https://weiblog-comments.netlify.app/ui` 这个页面是转发生成的，
它里面的脚本把接口地址写死成了 `https://weiblog-comments.vercel.app/api/`。
`vercel.app` 在国内被 DNS 污染，浏览器发的登录请求根本出不去，
所以看起来像「密码错」，其实是请求没发成功。

**修法（二选一，做一次就永久有效）**

- 方法 A（推荐，不用登 Vercel）：把 `_netlify_drop` 这个文件夹重新拖到 Netlify 部署一次。
  里面已经放好了改过的 `ui/index.html`（接口地址指向 Netlify 自己）和 `ui/admin.js`
  （后台脚本存本地，不再依赖 unpkg，国内打开快很多）。
  具体：Netlify 站点 → **Deploys** → 页面底部 **Deploy manually** 的虚线框 → 把 `_netlify_drop` 文件夹拖进去。
  之后统一用 **https://weiblog-comments.netlify.app/ui** 登录，不用 VPN，也不用再记那串带哈希的 vercel 地址。
  > 注意：拖的必须是整个 `_netlify_drop` 文件夹（里面还有 `_redirects` 这个转发规则文件）。
  > 少拖它，评论接口就会 404，页面上留言也会跟着挂。
- 方法 B（一步到位）：Vercel 项目 → Settings → Environment Variables → 加一条
  `SERVER_URL` = `https://weiblog-comments.netlify.app` → 重新部署一次。
  这样 Vercel 自己吐出来的 `/ui` 也会指向 Netlify。

> 博客页面上的留言组件本来就用的 Netlify 地址，所以访客留言一直正常，只有后台受影响。

### 2. GitHub 时不时连不上

分两种情况，处理方式不一样：

**a) 从本地发布**（`1-发布到网站.bat`）—— 已经自动处理好了。
以前只要 `github.com:443` 被断（`CONNECT tunnel failed` / 502），发布就整体失败。
现在脚本会**自动切换通道**：git 推不动，就改用 `api.github.com` 逐个文件提交，
通常能绕过去（`api.github.com` 在国内比 `github.com` 稳得多）。
黑窗口里看到「自动改用 api.github.com 通道重试」是正常提示，不是报错。

**b) 在浏览器里打开 github.com** —— 这个脚本管不了。
- 想改配置/看构建进度时才需要它，平时不用；
- 还是打不开就开代理，或者用手机热点（移动网络路由经常不一样）；
- **写文章完全不需要 github.com**：Pages CMS 走的是 `api.github.com`，本地后台走的是你自己电脑。

### 3. 写好的文章被"覆盖"了怎么办

**这次已经找回来了**：今天写的那篇《一点闲言碎语》原先存在 `日期2026年11月10日-1.md` 里
（文件名和内容对不上，是因为 Pages CMS 早期按标题生成文件名，标题改过文件名没跟着变）。
清理"看起来重复"的文件时被误删了，现已从 git 历史里取回，
恢复为 `source/_posts/2026-11-11-一点闲言碎语.md` 并重新上线。

**三道防线，以后不会再无声无息地丢**

1. **发布前自动备份**：每次双击 `1-发布到网站.bat`，都会先把整个 `source` 存一份到 `.backup/`（留最近 10 份）。
   出问题双击 `6-恢复备份.bat`，按提示选一份就能回到当时的样子。
2. **发布只增改、不删除**：本地少了的文件，发布时自动按线上版本保留，绝不会因为本地没这篇就把线上的删掉。
3. **新文章文件名带日期**：`2026-11-11-标题.md`，两篇同名也不会互相覆盖。

> 唯一还会删东西的地方：Pages CMS 里手动点删除。删之前先想一下，本地有备份可以兜底。

## 十、遇到问题

- **提示 `'node' 不是内部或外部命令`**：本机没装 Node.js。`_run.bat` 会自动去找可用的 node.exe（
  系统安装的 → `C:\Program Files\nodejs` → WorkBuddy 自带的那份），正常情况下双击 bat 不会报错。
  如果仍然报“Node.js not found”，装一个 [Node.js LTS](https://nodejs.org) 即可。
- **提示 4000 端口被占用**：说明已经有一个预览/后台窗口开着。这不是故障，直接用浏览器打开
  http://localhost:4000 就能用；想重启就先关掉那个黑窗口（按 `Ctrl + C`）再双击。
  实在想换端口：改 `run.js` 里两处 `4000` 为 `4001`。
- **手机上顶部菜单、右下角按钮、评论区一片空白（2026-11-14 已修）**：
  原因是图标字体、评论、分享这些资源原来从 `cdn.jsdelivr.net` 加载，国内网络经常连不上，
  加载失败时图标就全是空白。现在已经全部改成**随站点一起发布**（文件在 `source/libs/` 里），
  不再依赖任何外网 CDN。升级主题依赖版本时：下载新版放进 `source/libs/` 对应目录，
  再改 `_config.butterfly.yml` 顶部 `CDN:` 里的 `?v=` 数字即可。
- **页面样式没更新**：`1-发布到网站.bat` 会先清理再生成，正常不会出现；本地预览按 `Ctrl+F5` 强刷。- **文章 404**：检查文件名和 front-matter 里的 `title`、`date` 是否正常。
- **发布失败**：`1-发布到网站.bat` 现在会把 git 的原始报错原样打出来，并直接说明原因（令牌无效 / 网络代理 / 目录权限）。
  按它给的提示处理即可，不用猜。最常见两种：
  - 令牌被拒（`Authentication failed`）→ 重新生成令牌，跑 `5-首次配置GitHub.bat` 覆盖；
  - 连不上 GitHub（`CONNECT tunnel` / `Could not resolve host`）→ 关掉代理或加速器再试。
- **同步提示「两边都改过」**：说明同一篇本地和线上各改了一版，脚本保留了本地那份。
  想要线上那版：把这篇文章删掉（或改名）再双击 `4-同步云端文章.bat`；想让线上用本地这版：直接 `1-发布到网站.bat`。
- **任何报错**：把黑窗口里 `—— git 原始输出 ——` 那几行发给我即可，前面的生成列表不用带。
